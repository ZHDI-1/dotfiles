# 重构

重构让读者更快得到结论、更容易核对证据，同时不改变技术内容。

## 流程

1. 通读全文，判断类型和当前结论状态。留意类型是否已经变化，例如 WIP 实际上已经确认根因。
2. 盘点：
   - 每个结论及其所有证明位置；
   - 每项证据（图、日志、代码、数据）及其支撑的结论；
   - 背景知识、机制说明、排查过程记录、被排除的假设；
   - 内部不一致：同一事实的不同数值、同一机制的不同描述。
3. 为每个结论确定唯一的主要证明位置，通常选证据最完整、上下文最自然的一处；其余位置改为一句话复述加引用。
4. 按 evidence-rules.md 的“主阅读路径与附录”划分主文和附录。
5. 重写状态块。
6. 调整段落，让每段回答一个新疑问。只是在重复已回答问题的段落，把其中的素材按去向表处理。
7. 逐项核对没有素材丢失；有素材被合并或移入附录时，只把这些条目记入去向表。
8. 用 review.md 的“常见必须修改项”自检。

## 不改变的内容

- 日志、代码、命令输出、数值、时间戳、版本号、标识符原样保留。
- 结论状态和措辞强度不擅自提升。
- 作者的取舍（例如选定的修复方案）不替换；有疑问列为问题。

## 素材去向表

示例：

| 原位置 | 内容 | 去向 | 说明 |
|---|---|---|---|
| §2 第 3 段 | 重连机制背景 | 附录 B | 主文 §3 保留一句话 |
| §4 时序图 | 竞争窗口的构造时序 | §3.2 | 补标为构造时序 |
| §5 第 1–2 段 | 根因复述 | 合并 | 与 §3.1 重复，改为引用 |

“合并”只用于与另一处完全重复的内容，并注明重复位置。有素材被合并或移入附录时，去向表随结果一起交付，供作者核对；只调整顺序、标题或措辞时不附表。

## 精简请求

精简压缩的是主阅读路径，不是素材总量：

- 先合并重复证明、删去复述，再把背景和过程记录移入附录；
- 附录中内容的删除需要作者确认；
- 精简后的主文仍包含状态块、主要证明和可能推翻结论的未知。

## 分步交付

文档很长或结构改动很大时，可以先交付重构方案（新目录、主要证明位置、去向表草案），确认后再改写全文。用户已明确要全文时直接给全文。

## 交付内容

- 重构后的全文；
- 素材去向表（仅在有合并或移入附录时）；
- 结构变化的简述（一到三句）；
- 降级措辞的逐条说明（原句、改后、原因）；
- 发现的问题，按 review.md 分级，必须修改项单独列出。
