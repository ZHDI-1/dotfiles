# 评审

必须修改的判定标准和停止条件定义在 SKILL.md。这里给出评审前的确认、常见问题清单和输出格式。

目录：评审前确认｜常见必须修改项｜可选改进｜输出格式｜复审输出

## 评审前确认

- 类型：按该类型读者的问题来读。不用根因分析的标准要求现场文档给出根因，也不因为 WIP 没有结论而判它不合格。
- 依据：只有文档，还是另有原始材料。只有文档时，评审范围是内部一致性和结论与证据的匹配。
- 范围：用户只要某几节的意见时，只评这几节；其他部分若有必须修改问题，简短提一句。

## 常见必须修改项

以下问题在多数情况下会导致误判。判定时仍要说出具体误导了哪个判断，说不出来的降为可选改进。

- 结论状态缺失或与证据不符：推断写成已确认，WIP 写成定论。
- 只有相关或时间先后，就称为主因。
- 因果链中没有证据的一跳用事实口吻陈述；或链条终点对不上开头描述的现象。
- 声称已确认根因，触发条件既未说明也未列入未知；或把未证实的触发条件写成事实。
- 不同时刻、对象或版本的证据合并推理而未标注，且推断依赖它们相同。
- 跨节点时序依赖时间戳，时钟误差可能大于需要区分的间隔，却未说明。
- 代码证据与线上运行版本不一致，且差异可能影响结论。
- 构造时序未标注，读者会当作线上真实路径。
- 用注入或放大条件下的复现，证明线上确实走了该路径。
- 修复没有对应失效前提却称为根治，或验证范围被夸大。
- 同一证据在多处被当作独立佐证。
- 重复证明导致前后不一致：数值、顺序或机制细节不同。
- 已知与结论矛盾的观测被省略，或可能推翻结论的未知没有列出。
- 多 case 汇总中把同症状归为同根因，或用强 case 的证据支撑弱 case。
- 时间、数值、版本、标识符错误，且影响推理。

## 可选改进

分两组，结构类优先：

- 结构与阅读效率：主阅读路径过长；重复证明但未造成不一致；背景、过程记录、机制说明混在主路径；段落没有回答新疑问；素材缺少证明作用说明但不致误读。
- 语言：措辞、术语一致性、标点和中英文混排（沿用文档已有约定）。

只列收益最高的几条，通常不超过五条；不为凑数提意见。

## 输出格式

按下面的结构输出，没有内容的部分省略：

```text
## 评审结论
<可以定稿 | 关闭必须修改项后可以定稿 | 主要结论需要降级或补证据>
<一句话说明主要原因>
评审依据：<仅文档，未核对原始材料 | 文档与原始材料>

## 必须修改（N 条）
1. <位置>：<引用原文或概述问题>
   误导：<读者会误以为什么，影响哪个判断>
   修改：<补充哪些证据>；或<降级为怎样的表述，并列入未知>
   关闭条件：<改到什么程度即可关闭>

## 可选改进（可不改）
- <位置>：<建议>

## 已核对
- <一两句说明哪些关键点已经没有问题，避免下一轮重复检查>

## 停止条件
以上必须修改项关闭后即可定稿；可选改进不影响定稿，也不作为复审依据。
```

示例条目：

```text
1. §3 第 2 段：“CPU 瓶颈是延迟升高的主因”
   误导：读者会认为降低 CPU 占用即可解决，并据此判断修复方向。
   修改：补充能区分先后的证据（如更细粒度的指标或调度延迟数据）；或改为“候选因素”，并把“CPU 升高是原因还是结果”列入未知。
   关闭条件：措辞与证据等级一致，且未知中有该项。
```

## 复审输出

```text
## 复审结论
<可以定稿 | 可以定稿（另有 N 条已记录分歧） | 仍有 N 条必须修改>

## 上轮必须修改项
1. <已关闭 | 未关闭：还差什么>

## 已记录分歧
- <作者不接受的必须修改项及其可能导致的误判；没有则省略>

## 本轮新问题
<仅限改动处引入的必须修改问题，或标注“上轮遗漏”的必须修改问题；没有则写“无”>
```

复审不附新的可选改进清单。
